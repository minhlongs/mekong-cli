Key Design Decisions - **OutcomeRecorder uses MemoryBridge as primary store** with in-memory index as instant fallback (avoids MagicMock breakage in tests; degrades gracefully if MemoryBridge backend is missing). - **`find_similar_failures` dual-path**: tries MemoryBridge.search() first (semantic/vector), then filters the in-memory index. Both paths apply metadata-level filtering (error_type, provider, command). - **Singleton pattern** matches existing Mekong conventions (`OutcomeRecorder.get_instance()`). - **`_reset_singleton()` test helper** exported from `outcome_recorder` for test isolation. - **`attach_learning_hooks()`** wraps the StageRetryExecutor's `on_retry` callback — zero changes to executor.py required. ## 6. Auto-Tune Logic (D4) `suggest_retry_threshold()`: - No history -> return current. - avg retries >= current -> raise by 1 (up to max_threshold). - avg retries < 0.4 × current -> lower by 1 (min 1). - Otherwise unchanged. ## 7. Error Classification `_classify_error()` maps error messages to categories: timeout, auth, rate_limit, connection, forbidden, context_length. Checks specific patterns first (timeout before connection because "Connection timed out" should map to connection, while pure "timeout" maps to timeout). ## 8. Integration with C3 Retry Loop `StageRetryExecutor` has `on_retry` callback. `attach_learning_hooks()` wraps it: 1. Original callback fires first (logging, etc.) 2. Then `_check_pattern_warning()` queries MemoryBridge; if 2+ similar past failures exist, logs a `WARNING`-level message. 3. Outcome is recorded automatically. ## 9.
