## How to read this document

The denominator is the advertised snapshot: **197 command groups**. Claims are
never deleted, merged or re-worded to improve a ratio — a claim that has no executable
operation is reported as `NOT_IMPLEMENTED` here, in `GET /v1/cli/capabilities` and at
runtime (`NO_OPERATION_BINDING`), and the milestone gates stay unmet until the business
condition is measured from persisted facts.

Column meanings:

- **execution** — `EXECUTABLE` when at least one `OperationSpec` is bound to the command
  (schema validation → job → real handler → postconditions → evidence → signed receipt);
  `NOT_IMPLEMENTED` when the command is advertised but has no bound operation yet.
- **bound operations** — `op_id`s reachable through `mekong <command> <subcommand>` and
  `POST /v1/cli/runs`.
- **proof** — the test that asserts the business result of the binding. A claim without a
  proof test is not accepted as complete, whatever its HTTP status code says.
- **sample_output in the ledger is documentation only** — it is never used as evidence of a
  run (see `docs/cli-promise/STATUS.md`).
